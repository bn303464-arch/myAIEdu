# /develop

사용법: `/develop [만들 메뉴 추천 기능을 자연어로]`

예시
- `/develop 기분과 시간을 고르면 메뉴 3개를 추천해줘`
- `/develop 오늘 먹은 메뉴를 저장하고 같은 메뉴가 반복되지 않게 추천해줘`

## 실행 파이프라인

기능 설명이 비어 있으면 무엇을 만들지 한 번만 묻고 멈춘다.

### 1단계: 기획 (plan)
- `plan` 에이전트에게 기능 설명을 전달한다.
- 산출물: `docs/plan-<기능명>.md` (요구사항, API 계약, 데이터 모델, 화면 목록, 완료 기준)
- **확인 필요** 항목이 있으면 파이프라인을 멈추고 사용자에게 묻는다. 답을 받은 뒤 1단계를 다시 실행한다.

### 2단계: 백엔드 구현 (dev)
- `dev` 에이전트에게 기획서 경로를 전달하고, **백엔드 범위만** 맡긴다 (`backend/`, `backend/tests/`).
- 완료 조건: `python -m pytest backend/tests -q` 전체 통과.
- 실패하면 `dev` 에게 실패 출력을 넘겨 고치게 하고, 최대 2회까지 반복한다. 그래도 실패하면 멈추고 보고한다.

### 3단계: 프론트엔드 로직 (dev)
- `dev` 에이전트에게 같은 기획서를 주고, **프론트엔드 JavaScript 범위만** 맡긴다 (`frontend/js/`, 마크업의 `id`·`data-*` 속성).
- 2단계에서 만든 API 계약과 실제 응답이 일치하는지 확인하도록 전달한다.

### 4단계: 화면 디자인 (design)
- `design` 에이전트에게 기획서의 화면 목록과 3단계 결과(추가된 `id`·구조)를 전달한다.
- 담당: `frontend/index.html` 의 구조, `frontend/css/`. JavaScript 로직은 건드리지 않게 한다.
- 디자인 방향(배달 앱 감성, 360px 모바일 우선, 밝은 모드·다크 모드)은 design 에이전트 정의를 따른다.

### 5단계: 검증
- 테스트를 다시 실행한다: `python -m pytest backend/tests -q`
- 서버를 띄운다: `uvicorn app.main:app --app-dir backend`. 기획서의 API 경로마다 요청을 보내 응답 모양이 계약과 같은지 확인한다.
- 확인하지 못한 항목(예: 브라우저 화면 확인)은 그대로 "확인 못함"으로 적는다.

## 최종 보고
파이프라인이 끝나면 아래 형식으로 한 번에 보고한다.

```
[기능] <기능 설명>
[기획서] docs/plan-<기능명>.md
[백엔드] 변경 파일 / 테스트 결과
[프론트엔드] 변경 파일 / 연결된 API
[디자인] 변경 파일 / 확인 여부
[검증] 테스트 · 서버 확인 결과
[남은 일] 확인 필요 항목, 확인하지 못한 항목
```

파이프라인 중간에 실패하면 어느 단계에서 멈췄는지와 실패 출력을 함께 보고하고, 이미 끝난 단계의 결과는 그대로 남겨 둔다.
